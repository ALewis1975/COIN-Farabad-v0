## Persistence clock contract (F05)

Core and CIVSUB retain their existing storage keys and tuple/record layouts. Add an envelope pair `persistenceClock = [1, savedServerTime, systemTimeUTC, "FREEZE_OFFLINE"]`; version 1 describes the clock sub-schema. No wall-clock catch-up: a deadline with 600 seconds remaining at save has 600 seconds remaining immediately after load, regardless of server downtime. Durations, coordinates, strengths, counters, calendar dates and IDs are not timestamp-shifted.

Core uses existing `s1RegistryUpdatedAt` as the exact legacy save anchor when present: the current main save function writes it on every save. CIVSUB legacy blobs have no reliable save anchor. Their first migration retains campaign/identity/influence data, clamps lead/attack cooldowns to their configured baseline maximum (3600/1800 seconds), resets transient elapsed-time anchors, and logs the conservative fallback. No guessed legacy save time. A one-slot pre-clock backup is retained in each owner's namespace, then overwritten only by an explicit reset. New-format saves always use their own anchor. A core save older than the current baseline with neither a valid clock envelope nor s1RegistryUpdatedAt is quarantined: boot and saves stop with the original profile intact until an operator supplies a verified anchor or explicitly resets. The loader never silently discards that campaign.

Load helpers deep-copy the payload, translate only explicitly enumerated timestamp fields and positional record slots, and leave persisted input untouched. Deadline sentinels remain sentinels; elapsed/audit stamps may precede the new process clock where their consumers allow it. Execution-start flags requiring nonnegative values remain valid and preserve outstanding arrival/deadline budgets. Tick/decay anchors restart at load, avoiding offline drain and catch-up bursts. Unknown/future clock versions must fail closed without replacing the campaign with defaults. The live snapshot includes clock schema, source anchor, target anchor and migration policy for diagnostics. Reset clears clock backup/migration state and immediately saves a clean anchored campaign. The accepted objective may be recreated as a world object after restart; that recreation must retain translated execution budgets, accumulated progress and the parked VBIED pause/countdown. The additive activeVbiedElapsedBeforeLoad duration carries elapsed time that nonnegative engine sentinels cannot represent after rebasing; it resets only for a new manifestation or cleanup.
